# Updating the living Games library

One catalog powers the interactive app and the actual GitHub Wiki. Original recommendations and browser preferences keep their stable IDs.

## Canonical inputs

| Source | Purpose |
|:--|:--|
| `data/seeds.tsv` | Original 170 roguelite recommendations. Never replace this with a new genre list. |
| `data/shooters-seeds.json` | Steam shooter discovery candidates and explicit reconciliation dispositions. |
| `data/shooters-steam.json` | Verified official Steam metadata, reviews, artwork, and trailers. |
| `data/shooters-external.json` | Researched creator-hosted games, mods, demos, requirements, native ratings, and source evidence. |
| `data/shooters-curation.json` | Editorial explanations, confidence, alternate stores, and verified creator-support links. |
| `data/storefront-discovery.json` | Exact alternate-store candidates, accepted direct destinations, and per-game coverage. |
| `data/media-completion.json` | Reviewed video provenance, edition labels, and verified store corrections. Applied after automated discovery. |
| `data/source-editions.json` | Public creator-store edition evidence; full game versus demo is explicit. |
| `data/catalog.json` | Merged current snapshot, with one record per stable ID. Generated by the build. |

Steam records use `steam:APPID`. Non-Steam records use `external:STABLE-PROJECT-KEY`. Do not assign a new ID because a title changes. Multiple stores are links on one record, not duplicate games. Different public prototype/standalone/DLC editions must explain their distinction.

## Refresh the shooter collection

Use **Actions > Expand shooter library > Run workflow**, or run:

```bash
python3 -m pip install -r requirements-dev.txt
python3 scripts/collect_shooters.py
python3 scripts/collect_external_media.py
python3 scripts/build.py
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tests/browser_qa.py
python3 tests/multiplatform_qa.py
python3 tests/source_completion_qa.py
python3 scripts/media_qa.py
```

The Steam collector skips unchanged verified records younger than 24 hours. The creator-media collector keeps prior media if a site fails. Its `--force` option bypasses the media age check. Editorial facts, release status, mod requirements, and membership claims are manually reviewed; scraping artwork does not automatically verify those fields.

The generated native wiki and the interactive build are published by **Publish library** after successful source collection. That workflow tests the actual packaged HTML in Chrome, pushes the real `.wiki.git` repository, creates a downloadable release, and deploys Pages when the repository has Pages enabled. The `wiki/` directory alone is not proof of publication.

## Adding a Steam recommendation

Use the repository's **Add a game** issue form for the original workflow, or append an exact-name shooter candidate to `data/shooters-seeds.json` with its collection, editorial fit, and preferably confirmed app ID. Inspect any unresolved result. Never silently accept a similarly named game, soundtrack, demo, or sequel.

## Adding an off-Steam recommendation

Add a record to `data/shooters-external.json` using an existing entry as a schema example. Required facts include a stable ID, exact public project URL, creator, build type, availability, explicit prerequisites, sources, verification date, and an editorial explanation. Unknown dates and ratings remain null.

Use `storefronts[].kind = support` for Patreon or similar support pages. Do not imply that subscribing buys the full game or grants a private build unless that exact current tier has been verified. This catalog does not inspect member-only posts.

Native ratings retain their actual scale and sample: an itch.io 4.8/5 is not a Steam 96% positive review score. The app has separate Steam and native-host rating filters and sorting. Native-host sorting orders fractions of each source scale while continuing to display those original scales.

Release dates and update dates are separate. A 2026 patch does not make a 2021 game a 2026 launch. Year-only dates are labelled as such. Public demos and prototypes are available to try, but are never labelled as full released games.

## Browser state and backups

Favorites, notes, personal ratings, play status, and saved views live in browser storage under the existing `games.library.v1` key. Export/import a personal backup to move devices. Catalog refresh never uploads personal data. Automatic cross-device sync is not implemented.

The app indexes every record and never uses viewport virtualization. It works from a local snapshot; uncached artwork and videos require a connection. YouTube creator embeds load only after a user chooses to play. Official source links remain available if embedding fails.

## Publication and verification

Keep `docs/EXECUTION.md` as the consolidated continuity record. Archive releases with their source revision, catalog hash, HTML hash/size, QA evidence, and source package. Preserve unrelated native wiki pages. Do not rerun old bootstrap payloads over newer source revisions: the installer checks both source and target hashes and refuses conflicts.

## Complete media and storefront coverage

Every published shooter must have an actual source image, at least one embedded video source, and a non-support distribution link. `test_source_completion.py` enforces this across the entire shooter collection and matching visual wiki atlas. `source_completion_qa.py` opens every game detail in the actual app, checks every published store button, decodes every card image from real bytes, verifies added YouTube titles, and plays the new Shrine stream. These are separate from the original catalog and cross-platform regressions.

The wiki Media Atlas embeds artwork and links exact videos. GitHub wiki Markdown does not run arbitrary video players; the portable HTML and Pages site provide the embedded players. Community gameplay and official trailers are explicitly credited.

Run `python3 scripts/discover_storefronts.py` for a bounded GOG/itch.io/official-website pass. Discovery is not proof of worldwide retail completeness. Unmatched stores remain unconfirmed, not absent. Inspect the returned candidate list for editions and same-name projects. Keep support, full purchases, demos, original mod downloads, and newer remakes separate. Manual edition corrections in `media-completion.json` prevent a later automated refresh from silently turning a demo back into a full-game store.
